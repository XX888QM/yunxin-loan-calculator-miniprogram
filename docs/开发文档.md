# 车贷房贷计算器微信小程序开发文档

## 1. 产品定位

做一个面向普通用户和车商/房产销售的贷款计算工具，核心不是只算月供，而是把常见的“月息”“平息”“手续费”“等额本息”口径拆开，帮用户看清真实资金成本。

一句话：先用四步报价体检把合同现金流、费用和尾款填齐，再用专业工具核对月供、总利息、还款明细、真实年化、提前还款和落地总价。

## 2. 目标用户

- 买车贷款用户：想知道销售口中的月息到底贵不贵。
- 房贷用户：想快速计算商贷、公积金、组合贷和提前还款。
- 车商业务人员：给客户展示不同首付、期数、利率下的真实成本。
- 云鑫租车后续平台：可作为客户报价、合同测算和真实利率说明工具。

## 3. 核心功能

### 3.0 贷款类型

贷款类型：

- 车贷
- 房贷

选择 `组合贷` 工具时，系统默认切到 `房贷`。

快捷期数：

- 车贷：12/24/36/48/60 期
- 房贷：5/10/20/30 年

工具显示：

- 车贷：算月供、折算利率、平息换算、尾款贷、车贷落地总价
- 房贷：算月供、组合贷、反推本金、提前还款、LPR 情景

### 3.1 月供测算

输入：

- 贷款类型：车贷 / 房贷
- 输入方式：填贷款额 / 车价（房价）−首付（首付比例快捷 20/30/40/50% 或自定义金额）
- 贷款本金（或由车价−首付自动得出）
- 金额单位：元 / 万（房贷默认万，车贷默认元；切换单位或贷款类型时保持实际金额不变）
- 还款期数
- 利率
- 利率口径：年化% / 月利率%（按剩余本金递减计息）
- 还款方式

支持方式：

- 等额本息
- 等额本金
- 先息后本

输出：

- 首月/月供
- 末期还款
- 总利息
- 还款总额
- 完整还款明细

### 3.2 房贷组合贷

输入：

- 贷款类型：房贷
- 商贷本金
- 商贷利率
- 公积金本金
- 公积金利率
- 利率口径：年化% / 月息%
- 贷款年限
- 还款方式

输出：

- 合计月供
- 总利息
- 还款总额
- 每期本金、利息、余额

### 3.3 反推本金（月供预算）

输入：

- 月供预算
- 还款期数
- 利率
- 利率口径：年化% / 月息%
- 还款方式：等额本息 / 等额本金

输出：

- 最高可贷本金
- 首月/月供
- 总利息
- 还款总额
- 完整还款明细

用于回答“我每月最多还多少，大概能反推多少本金”，**不等于审批额度**。

### 3.4 真实利率反推

用于处理合同或还款计划已经给出实际现金流的情况。

输入：

- 贷款本金
- 还款结构：等额月供 / 尾款贷 / 先息后本
- 输入模式：知道月供 / 只知总利息
- 实际月供或每期利息
- 尾款贷的末期尾款
- 前置费用：服务费、手续费等一次性费用（可留空）
- 还款期数
- 对外宣称年化% 或月息%（可留空）

限制：

- “只知总利息”仅按等额月供折算：月供 = (本金+总利息)/期数。
- 尾款贷和先息后本必须填写实际还款结构，不能仅用平均月供代替。
- 现金流不足或不存在有效非负 IRR 时返回明确错误，不显示伪 0%。

输出：

- 按还款现金流折算的月利率
- 名义年化、复利年化
- 含费月利率、含费名义年化、含费复利年化
- 总利息、总融资成本（总利息+前置费用）
- 与对外宣称口径的差值和倍数；宣称利率为空时显示“未填写”

典型场景：对外报价月息 0.59%，但实际等额现金流反推月利率约为 1.095%。

### 3.5 平息/月息换算

用于解释“月息”和“平息”不是同一个真实资金成本。

输入：

- 贷款本金
- 平息费率
- 平息口径：年化% / 月息%
- 还款期数

输出：

- 平息口径月供
- 总利息
- 反推后的折算月利率
- 名义年化
- 复利年化

关键说明：平息是按原始本金全期计息，实际资金占用会逐月减少，所以平息 0.59% 通常不等于折算月利率 0.59%。

### 3.6 提前还款：快速估算与账单/按日估算

快速估算适合先判断大致省息空间。

输入：

- 贷款本金
- 原还款方式：等额本息 / 等额本金
- 当前剩余本金（选填；填写后优先使用该值）
- 利率
- 利率口径：年化% / 月利率%
- 总期数
- 已还期数
- 提前还款金额
- 违约金：比例%（按实际提前还款额）或固定金额，二选一
- 处理方式：缩短期限 / 降低月供

输出：

- 当前剩余本金
- 提前还款后本金
- 预计节省利息
- 违约金
- 净省（节省利息−违约金，可为负，负值红色提示不划算）
- 新剩余期数
- 新月供

账单/按日估算适合手里已有还款账单时再核对一次。

额外输入：

- 当前剩余本金、剩余期数、年利率、提前归还本金
- 账单模式：账单应计利息
- 按日模式：最近结息日、提前还款日、日计数约定（ACT/365F、ACT/360、30/360）
- 违约金：固定金额、按提前还款额比例、按剩余本金比例
- 处理方式：缩短期限 / 降低月供

限制：只支持正常等额本息或等额本金、固定利率、无逾期/跳期、无尾款的剩余计划。账单应计利息只用于本次结算期；后续计划仍是固定利率假设下的估算，不能称为机构精确结清金额。

快速估算拦截已还满期、余额超过原本金及提前还款超过剩余本金。填写的当前余额与原计划推算值不同时，按当前余额、当前利率和剩余期数重建还款计划进行估算；重建月供及节省利息不等于银行账单，最终以最新还款计划和结清试算单为准。

### 3.7 尾款贷（气球贷）

车贷常见的低月供+大尾款方案。

输入：

- 贷款本金
- 还款期数
- 利率（年化% / 月息%）
- 尾款：比例快捷 30/40/50% 或自定义金额；超过本金时提示错误，不静默夹值

输出：

- 月供（前 n−1 期等额）
- 末期还款（月供+尾款）
- 总利息、还款总额
- 对比同参数等额本息的月供和总利息
- 完整还款明细

### 3.8 四步贷款报价体检

首页默认入口，步骤为：

- 页面底部显示当前小程序版本号，版本主值取自 `app.js` 的 `globalData.version`。

1. 选择用途：买车 / 买房。
2. 填贷款本金和期数。
3. 填还款结构、每期还款、尾款、前置费用、每期费用、对外利率和提前还款规则是否已知。
4. 查看按现金流反推的复利年化、已录入成本合计、最高每期还款、末期还款和签约前核对项。

费用状态：

- 已确认无额外费用：按 0 计算，但仍提示签约前再核对服务费、GPS、保险等项目。
- 已填写额外费用：把前置费用、每期费用和尾款计入现金流。
- 未选择费用状态：视为费用尚未确认，结果只代表已录入项目的最低口径；不能加入横向报价对比，也不能把未填写费用当成 0。

报价对比：

- 用户手动加入临时对比，最多 3 份，不自动保存、不自动推荐哪份“更划算”。
- 对比区只适合看同一用途、费用已确认的报价；不同用途或未确认费用不能直接判断优劣。

报告与历史：

- 可复制、导出报价体检 PDF、手动保存到本机。
- 最多保存 30 份报价体检记录；只保存经过字段白名单处理的测算数据，不保存姓名、手机号、证件号、邮箱、地址等身份信息。
- 读取历史失败、数据损坏或版本不兼容时禁止保存和删除单条，防止覆盖原数据。
- 对可读取但损坏或不兼容的历史，记录页提供确认清空入口；读取失败时不清除原数据。
- PDF 在小程序本机用户文件目录生成并打开，不上传到服务端。
- 历史页提供导出 PDF 清理入口，仅在用户确认后删除本小程序命名的导出文件，并提醒先完成分享或保存。

### 3.9 全款 vs 分期车贷落地总价

输入：

- 全款车价、分期车价、优惠
- 购置税、保险、上牌、必选装
- 实际用于购车的贷款金额、合同总还款、每期费用、前置费用
- 前置费用支付方式：现金另付 / 从放款中代扣

输出：

- 全款落地总价、分期落地总价、首期需拿出的现金、融资成本、分期总支付和相对全款的差额

规则：购车落地价与融资成本分开；贷款金额、首付和前置费用只按其实际支付路径算一次，避免重复计入。购置税、保险等均由用户按实际合同/报价填写，不内置政策税率。

### 3.10 LPR 手动情景

输入：

- 本金、期数、还款方式
- 当前情景 LPR、合同加点（bp）
- 重定价期和重定价后的假设 LPR

输出：

- 当前和情景后的年利率、首期还款、重定价期当期还款、月供变化、总利息和还款明细

这是手动情景工具，不联网读取实时 LPR，也不替代合同中的重定价日、计息天数或特殊规则。

## 5. 页面结构

采用一个首页 + 报价体检 + 全部工具 + 本机记录的单页状态切换，不引入多页面路由。

原因：

- 首页先回答“这笔报价会不会漏算”，再让熟手直接进工具。
- 四步填写比把所有字段一次铺开更不容易漏掉费用和尾款。
- 保持原生小程序的轻量结构，计算、记录和 PDF 都在本机完成。

页面工具按贷款类型动态显示：

- 车贷：算月供、折算利率、平息换算、尾款贷、车贷落地总价
- 房贷：算月供、组合贷、反推本金、提前还款、LPR 情景

报价体检页面：

- 深蓝信息头 + 进度节点，四步依次填写用途、本金期数、还款费用、结果。
- 结果页突出复利年化、已录入成本合计、最高每期还款、末期还款；签约前核对项采用清单形式。
- 历史页仅展示手动保存的报价报告摘要，不显示身份信息。

还款明细支持设置首期年月，期数列按实际日历（YYYY-MM）显示，并支持本地导出 PDF；页面默认只展示前 12 期，完整明细走 PDF。分享入口作为自愿转发能力保留，不作为导出前置条件。

每个 Tab 结构：

- 贷款类型选择
- 工具场景说明 + 一键示例
- 输入区（首付/尾款比例即时显示约合金额）
- 一句话结论 + 复制结果
- 结果卡片
- 明细表（默认前 12 期）

## 6. 计算口径

### 6.1 等额本息

月利率：

```text
r = 年化利率 / 12
```

月供：

```text
月供 = 本金 * r * (1 + r)^期数 / ((1 + r)^期数 - 1)
```

每期：

```text
当期利息 = 剩余本金 * r
当期本金 = 月供 - 当期利息
剩余本金 = 上期剩余本金 - 当期本金
```

### 6.2 等额本金

每期本金固定：

```text
每期本金 = 本金 / 期数
```

每期：

```text
当期利息 = 剩余本金 * 月利率
当期还款 = 每期本金 + 当期利息
```

### 6.3 先息后本

每月先还利息，最后一期归还全部本金。

```text
每月利息 = 本金 * 月利率
最后一期还款 = 本金 + 每月利息
```

### 6.4 真实利率反推

通过完整月度现金流 IRR 反推。设第 i 期实际还款为 `CF_i`：

```text
本金 = Σ CF_i / (1 + r)^i
```

- 等额月供：每期现金流相同。
- 尾款贷：最后一期现金流 = 普通月供 + 尾款。
- 先息后本：前期为利息，最后一期为利息 + 本金。
- 含费口径：方程左侧改为净到手本金 = 名义本金 − 前置费用。

当前实现使用带求根区间验证的二分法。现金流总额低于本金、净到手本金不大于 0 或无法形成求根区间时，返回无效状态。

### 6.5 平息换算

平息总利息：

```text
总利息 = 本金 * 平息月费率 * 期数
```

平息月供：

```text
月供 = (本金 + 总利息) / 期数
```

再把这个月供放入 IRR 反推，得到折算月利率和折算年化。

### 6.6 尾款贷（气球贷）

尾款挂末期，其余部分按年金摊还：

```text
月供 = (本金 − 尾款 × (1+月利率)^-期数) × 月利率 / (1 − (1+月利率)^-期数)
末期还款 = 月供 + 尾款
```

零利率退化：月供 = (本金−尾款)/期数。

### 6.7 含费真实利率与违约金

- 含费真实利率：净到手本金 = 本金 − 前置费用，用同一 IRR 反推，费用越高含费利率越高。
- 提前还款违约金 = 实际提前还款额 × 比例（或固定金额），净省 = 节省利息 − 违约金，可为负。
- 快速估算的账单余额与原计划不一致时，先按该余额、当前利率和剩余期数重建剩余计划，再比较提前还款前后的预计利息。


### 6.8 分币入账与输入校验

- 理论月供先舍入到分；每期利息舍入到分；每期本金 = 当期还款 − 当期利息。
- 等额本金通过累计本金目标分摊余分，末期本金精确清零。
- 尾款贷和等额本息的最后一期根据实际剩余本金校正。
- 必须满足：本金合计=原本金、利息合计=总利息、还款合计=还款总额、末期余额=0。
- 等额本息按分计算出现提前结清或正常还款额不足以偿还本金时，页面禁止展示为正常计划并提示核对；正常分币尾差允许由末期调整，实际账单以合同和还款计划为准。
- 页面区分空值和合法的 0% 利率；期数、首付、尾款和前置费用不再静默夹值。

### 6.9 报价体检综合现金流

报价体检不把“费用没填”直接当作没有。已确认费用时，按实际现金流反推：

```text
第 0 期净到手金额 = 贷款本金 − 前置费用
第 i 期现金流 = 合同每期还款 + 每期附加费用
末期现金流 = 最后一期现金流 + 尾款（含尾款方案）
已录入成本合计 = 合同还款额 + 每期附加费用合计 + 前置费用 − 贷款本金
```

- 等额月供、含尾款、先息后本均按用户填写的实际现金流构造。
- 费用未确认时，仍可看到“已录入项目下限”，但不能用它比较报价或声称是完整成本。
- 对外利率只在同一计息口径下做提示；月利率、平息、名义年化、复利年化不能互相直接等同。

### 6.10 车贷落地总价与融资成本

```text
落地总价 = 车价 − 优惠 + 购置税 + 保险 + 上牌 + 必选装
首期现金 = 落地总价 − 实际用于购车的贷款金额 + 现金另付前置费用
融资成本 = 合同总还款 + 每期费用合计 + 现金另付前置费用 − 实际用于购车的贷款金额
分期总支付 = 首期现金 + 合同总还款 + 每期费用合计
```

前置费用若“从放款中代扣”，不再加到首期现金或融资成本里第二次；若现金另付，才按现金费用计入。工具只按填写数据计算，不推导税率、保险规则或交易政策。

### 6.11 LPR 手动情景

```text
情景年利率 = 手动 LPR + 合同加点（bp ÷ 100）
```

第一期用当前 LPR 情景；从用户填写的重定价期起，用新的假设 LPR 和同一合同加点计算。等额本息在重定价期按剩余本金和剩余期数重算月供；等额本金按当期余额继续计息。此处不查询实时 LPR，不模拟实际机构的重定价日或按日计息。

### 6.12 提前还款账单/按日估算

```text
本次预计结算支付 = 提前归还本金 + 应计利息 + 违约金
预计后续计划利息节省 = 原剩余计划利息 − 提前还款后剩余计划利息
预计净节省 = 预计后续计划利息节省 − 违约金
```

- 账单模式直接采用用户填写的“账单应计利息”。
- 按日模式按余额、年利率、天数和用户选择的 ACT/365F、ACT/360、30/360 估算应计利息。
- 缩短期限时尽量保持原还款结构的每期本金或月供；降低月供时保持原剩余期数。
- 该模式只把“本期应计利息”向账单靠拢，未来计划仍是估算；最终以合同、账单和结清试算单为准。

## 7. 技术方案

技术栈：

- 原生微信小程序
- WXML + WXSS + JavaScript
- 无第三方依赖
- 计算逻辑集中在 `utils/loan.js`

目录：

```text
app.js
app.json
app.wxss
project.config.json
sitemap.json
pages/index/index.js
pages/index/index.wxml
pages/index/index.wxss
utils/loan.js
utils/history.js
utils/pdf.js
tests/loan.test.js
tests/history.test.js
tests/pdf.test.js
tests/page.test.js
```

设计原则：

- 公式只写在 `utils/loan.js`
- 页面负责输入、单位转换、显式校验、展示、复制和本地文件调用
- `utils/history.js` 负责本机记录的字段白名单、身份信息过滤和 30 条上限；不承担业务计算
- `utils/pdf.js` 负责还款明细 PDF 与报价体检 PDF 的本地生成
- 引擎金额入参统一为元，还款明细按整数“分”入账
- 汇总金额全部从最终明细求和，保证本金、利息、还款和余额的不变量严格成立
- 所有金额展示保留 2 位小数，不使用千分位逗号（如 `6752.28`）
- 年化%输入使用百分比，例如 `13.14` 表示 13.14%。
- 普通月利率%输入使用百分比，例如 `0.59` 表示月利率0.59%，按剩余本金递减计息。
- 普通利率选择月利率%时按 `月利率 * 12` 折算为名义年化。
- 平息选择年化%时按 `年费率 / 12` 折算为月费率。
- 折算月利率展示到 4 位百分比，方便看出细微差异

## 8. UI 方向

风格：深蓝的报价体检引导 + 克制、清楚、可信的金融工具页。

视觉要求：

- 首页先显示“贷款报价体检”，并保留“直接使用全部工具”的入口。
- 四步进度和当前步骤清楚可见；大卡片选择买车/买房，避免一上来就堆参数。
- 重点数字放大显示，报价结果优先展示复利年化、已录入成本合计、最高每期和末期还款。
- 未确认费用用明确文字提示“下限/暂不适合比较”，不靠颜色暗示风险结论。
- 明细表默认展示前 12 期，完整明细走本地 PDF；金额列支持横向滚动。

### 9.5 报价体检费用边界

- 费用状态未选择：结果必须标记为已录入项目下限，且不能加入报价对比。
- 费用状态为“无额外费用”：前置费用、每期费用按 0 计，但结果清单仍提示用户核对可能单列的费用。
- 已填前置费用、每期费用、尾款：这些金额必须进入 IRR 现金流和已录入成本合计。

### 9.6 车贷、LPR、提前还款和本机历史

- 车贷落地总价：现金另付与放款代扣前置费用不能重复计入；分期总支付 = 落地总价 + 融资成本。
- LPR 情景：重定价期的利率和月供应按手动输入的 LPR + 加点变化；页面必须说明非实时查询。
- 提前还款：账单模式取账单应计利息；按日模式验证三种日计数；有逾期、浮动利率或尾款时应明确拒绝账单/按日模式。
- 本机历史：最多 30 条、按时间倒序、身份信息样式的文本不能写入存储；报价 PDF 能在本机生成。

## 11. 合规和文案边界

页面文案不要直接写“机构骗人”或给某份报价下欺诈/违法结论。

建议用：

- 真实资金成本
- 宣称口径
- 平息口径
- 反推年化
- 费用尚未确认，不能当作 0
- 手动 LPR 情景，不是实时利率
- 仅供测算，具体以合同、还款计划、账单和结清试算单为准

必须避免：

- 把账单/按日模式称为“精确结清”或“保证结清金额”。
- 把未确认费用按 0 或据此给“最划算”结论。
- 把 LPR 情景说成实时查询或真实重定价结果。
